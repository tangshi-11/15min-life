# 技术设计文档

项目：15分钟生活圈 · 智能体检与规划助手
版本：1.0.0 ｜ 日期：2026-10-01

---

## 1. 需求与目标

国家推行「15分钟便民生活圈」建设，要求居民步行 15 分钟内可获得基础医疗、教育、购物、养老等服务。
传统社区评估依赖人工普查与静态数据，缺乏对**真实可达性**的动态考量（道路非直线，红绿灯、过街天桥、
施工围挡等都会显著影响步行可达范围）。

本系统目标：基于百度地图开放能力，输入任意社区中心点，自动计算**基于真实路网的 15 分钟步行等时圈**，
统计圈内民生设施覆盖，识别 1km 服务盲区，输出可视化体检报告。

## 2. 系统架构

```
┌────────────────────────────── 前端（静态页，FastAPI 托管） ─────────────────────────────┐
│  Leaflet + 多源瓦片底图（高德优先，Carto/Esri/OSM 自动兜底，无密钥可演示）｜ 坐标统一由 BD-09 → WGS-84 转换后渲染                  │
│  等时圈多边形 / 步行热力场(网格) / 灰色区域 / POI 分类标注 / 中心点拖拽 / ECharts 雷达+柱状  │
└───────────────┬──────────────────────────────────────────────────────────────┘
                │ HTTP POST /api/inspect
┌───────────────▼──────────────────────── 后端（FastAPI, Python） ────────────────────────┐
│  编排：中心点解析 → 等时圈计算 → POI 采集清洗 → 盲区识别 → 体检报告                          │
│  ┌───────────────┐  ┌──────────────────┐  ┌───────────────────┐  ┌──────────────────┐  │
│  │ BaiduClient   │  │ isochrone 引擎    │  │ poi_cleaner 清洗   │  │ blind_spot 识别   │  │
│  │ 地理编码/POI/  │→│ 扇区采样→批量测时  │→│ 去重/纠偏/类别映射  │→│ 网格化→覆盖判定    │  │
│  │ 算路/批量算路  │  │ →边界→IDW→等值线  │  │                   │  │ →连通簇→灰色区域  │  │
│  └───────────────┘  └──────────────────┘  └───────────────────┘  └──────────────────┘  │
│  令牌桶限流 + 指数退避重试 + 失败自动降级（MockBaiduClient）                                │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

- **坐标口径**：百度接口默认 BD-09；前端底图为 WGS-84。后端提供完整 BD-09/GCJ-02/WGS-84 互转，
  前端同样内置转换函数，保证渲染与计算口径一致。
- **双数据源**：`BaiduClient`（实时）与 `MockBaiduClient`（演示/降级）实现相同接口契约，可无缝切换。

## 3. 地图 API 调用策略

### 3.1 接口清单

| 能力 | 接口 | 用途 |
|---|---|---|
| 地理编码 | `GET /geocoding/v3/` | 地址 → 中心点坐标 |
| 逆地理编码 | `GET /reverse_geocoding/v3/` | 坐标 → 地址标签 |
| POI 检索 | `GET /place/v2/search` | 按分类圆形区域分页拉取设施 |
| 步行路线规划 | `GET /directionlite/v1/walking` | 单点对步行测时 |
| 批量算路（路线矩阵） | `GET /routematrix/v2/walking` | 一请求多组起终点测时（核心优化） |
| 批量合并服务 | `POST /batch` | 一次合并 ≤20 个子请求（预留优化） |

### 3.2 批量与并发策略（命中 30% 工程优化）

- **分块批量**：批量算路接口对「起终点个数之积」有限制（约 ≤100），因此将 480 个采样点按
  `MATRIX_CHUNK=90` 分块，每次 1 起点 × 90 终点，共 6 次请求完成全部测时，相比逐点调用
  `directionlite` 减少约 **80 倍请求数**。
- **令牌桶限流**：全局 `TokenBucket(rate=BAIDU_QPS)` 在每次请求前按令牌桶匀速放行，保证不触发
  平台 QPS 限流；令牌不足时自动等待。
- **指数退避重试**：网络错误与平台侧临时错误（HTTP 5xx、业务状态码非 0）自动重试 3 次，
  退避间隔 0.6s × 2^n。
- **批量合并服务**：已封装 `BaiduClient.batch()`，支持将多个正逆地理编码/算路子请求合并为一次
  HTTP 请求（≤20 个），进一步压缩请求量，可扩展用于多地址批量解析。

### 3.3 容错与降级（命中 30% 工程优化）

| 异常场景 | 处理 |
|---|---|
| AK 未配置 / FORCE_MOCK | 启动即切换 MockBaiduClient，全流程可演示 |
| 单个 POI 分类检索失败 | 该分类降级为演示数据，其他分类不受影响，返回 `warnings` |
| 等时圈批量算路失败 | 降级为演示测时结果，接口仍返回完整报告 |
| 逆地理编码失败 | 使用输入地址作为标签 |
| QPS 限流 / 配额超限 | 令牌桶排队 + 重试，重试耗尽后降级 |

### 3.4 与官方「门店选址」参考案例的对照

官方示例（`lbs.baidu.com/jsapi/demo/usecases/industry/locationselection.html`）提供：
地图选点与信息回填、按分类周边检索（餐饮/购物/银行/教育/医疗/酒店）、距离排序、交通站点检索。
**本题必须在它之上自行实现**（示例里没有的部分，本系统已全部实现）：

| 官方示例 | 本系统 |
|---|---|
| 直线距离画圆 | 扇形采样 + 步行算路 + 空间插值 → 真实路网等时圈 |
| 圆内设施清单 | 按等时圈（而非圆）筛选，覆盖率量化 |
| 无盲区判定 | 1km 网格化盲区识别 + 灰色区域可视化 |
| 无报告 | 分项/综合评分 + 雷达/柱状图 + 地图渲染 |

注：官方示例检索的交通站点（公交/地铁）能力已并入本系统（见第 5 节），作为体检报告的附属指标。

## 4. 等时圈生成算法设计（核心）

**目标**：在不获取底层路网数据的前提下，仅用百度地图分散点位的 API 测时结果，推导近似连通区域。

### 4.1 扇区采样

以中心点 O 为圆心，将平面按角度均分为 `D=24` 个扇区（每 15°）。每个扇区沿中轴线布设采样点：
距离 `d = 100, 200, …, 2000m`（步长 `S=100m`，最大半径 `R=2000m`），共 480 个采样点。

```
                    ↑ 90°
                  采样点
              ······│······
             ·      │      ·
       180° ────────O──────── 0°
             ·      │      ·
              ······│······
                    ↓ 270°
```

### 4.2 批量测时

以 O 为唯一起点、480 个采样点为终点，调用 `routematrix/v2/walking` 分块批量测时，
获得每个采样点的真实步行耗时 `t(d, θ)`（考虑真实路网、人行道、过街等约束）。

### 4.3 每方向边界提取

对每个扇区方向 θ，取「步行耗时 ≤ 15 分钟」的最远采样点；相邻测点间用**线性插值**细化边界：

```
d_boundary = d_ok + (T - t_ok) / (t_fail - t_ok) × (d_fail - d_ok)
```

得到 24 个边界点，连接即扇区边界多边形（兜底结果）。

### 4.4 IDW 空间插值（创新点）

对中心周边 `60×60` 网格节点 `P`，用全部 481 个已知测时点做**反距离加权插值**，估计节点步行时间：

```
t(P) = Σ(w_i · t_i) / Σ(w_i)，  w_i = 1 / d(P, P_i)²，取最近 16 点
```

输出「分钟场」矩阵——既作为等时圈判定依据，也直接作为前端**热力图**数据源。

### 4.5 Marching Squares 等值线

对分钟场以 `T=15min` 为阈值执行 Marching Squares，提取等值线并首尾连接成闭合多边形，
得到平滑的等时圈轮廓（多边形 + 热力场双重可视化）。

### 4.6 复杂度与性能

- 采样点 480，批量请求 6 次（受 QPS 限制 ~1-2s 完成）；
- IDW 网格 60×60=3600 节点 × 481 已知点 ≈ 173 万次距离运算（Python 约 1-2s，纯标准库无外部依赖）；
- 实测（演示模式）端到端 **~200ms**。

## 5. 多源 POI 数据清洗策略

1. **分页拉取**：`place/v2/search` 按 11 个检索分类（菜市场/药店/小学/医院/超市/公园/银行/养老院/美食/公交站/地铁站）
   圆形区域分页拉取，单类最多 5 页 × 20 条；
2. **去重**：按「名称 + 坐标（5 位小数）」组合去重，消除多源/多页重复；
3. **异常过滤**：剔除坐标非法（越界/非数值）与超出检索半径 5% 的点；
4. **坐标纠偏**：统一为 BD-09 口径，前端渲染时再转 WGS-84；
5. **类别映射**：检索分类 → 民生类别（菜市场/超市→购物，药店/医院→医疗，小学→教育，
   养老院→养老，公园→文体，美食→餐饮，公交站/地铁站→交通），并保留 `search_key` 原始类别（盲区判定使用）；
6. **关键词兜底**：对名称/标签做关键词规则推断，兼容多源数据口径不一致。

## 6. 服务盲区识别算法

- **规则**：中心点周边 1km 内没有「菜市场、药店、小学」中任一类的点位 = 服务盲区；
- **网格化**：1km 方形区域按 200m 边长网格化（约 10×10 格），每格中心点检查其 1km 缓冲区内
  三类设施是否齐备（POI 按网格索引加速，缓冲窗口 ±6 格）；
- **连通聚类**：对无覆盖格网做 8 邻域 BFS 聚类，得到独立盲区簇；
- **灰色区域**：每簇取格网角点凸包（Andrew 单调链）生成多边形，在地图标红；
- **报告**：汇总盲区簇数、网格数、缺失设施，并作为体检综合评分的扣分项（每簇 -5，上限 -20）。

## 7. 体检报告

- 等时圈内各民生类别设施数量统计（射线法点面判定；交通站点作为附属指标展示，不计入综合分）；
- 分项评分：`score(cat) = min(100, 数量 / 建议阈值 × 100)`，阈值（医疗2/教育1/购物3/养老1/文体1/餐饮5）；
- 综合评分：类别加权平均（权重 0.25/0.20/0.20/0.15/0.10/0.10）再减盲区扣分；
- 前端以雷达图 + 柱状图 + 大数字展示。

## 8. 测试与验证

`backend/tests/` 共 23 项单元测试，覆盖：

- 坐标转换往返、球面距离、米制偏移；
- 等时圈多边形生成、边界在范围内、阻挡方向收缩（验证路网约束生效）；
- POI 去重、异常过滤、类别映射（含交通站点类别推断）；
- 盲区识别（已知盲区命中、全覆盖无盲区）；
- 令牌桶限流与指数退避重试；
- API 端点（地址/坐标两种入参、参数校验）。

运行：`cd backend && python -m pytest -q`，25 项全部通过。

## 9. 部署

- Docker：`docker compose up --build`（Dockerfile 基于 python:3.11-slim，前后端一体镜像）；
- 本地：`scripts/start.bat`（Windows）/ `scripts/start.sh`（Linux/macOS），首次自动建虚拟环境；
- 密钥：`.env` 中 `BAIDU_AK_SERVER` 脱敏配置，`.env` 不入库。
